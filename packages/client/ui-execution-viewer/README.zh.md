# @deepseek-ai/dsh-client-ui-execution-viewer

[English](README.md) | 中文

## 概述

执行过程视图把一次会话的工作展示为一份扁平账本：每一行是一段推理或一次工具调用，并展示其类别、已记录标题、生命周期状态与耗时。选中一行会展开已记录的命令、参数、结果、失败码或推理文本。尚未结束的步骤会自己走秒。

该视图是独立于 Chat 与 Trajectory 的 Conversation target，因此不会与 Chat 的过程分组争夺同一批行。账本在浏览器侧从客户端已经持有的事件窗口折叠而来：不新增 Host 服务、Remote 面、会话事件类型，也不声明配置。

<a id="use-this-package"></a>
## 使用本包

在会话的视图环里打开执行过程页签。步骤按 `anchorSeq` 顺序出现在所属轮次之下；重连或向前翻页之后账本得到相同结论——它读取持久事件，实时分片只是对持久结算的预告。

一行展示它的类别（读取、搜索、运行、网页搜索、子代理、计划，以及其余已记录类别）、由已记录参数得到的结构化标题、生命周期与耗时。状态依次是：调用提交前的 `preparing`、等待结果的 `running`、结果到达时的 `succeeded` 或 `failed`，以及轮次已关闭却始终没有结果的 `unfinished`。推理行报告 `running`、`succeeded` 或 `interrupted`。

选中一行会展开由槽位拥有的详情主体，它渲染已记录的命令、原始参数 JSON、结果文本、失败码或推理文本。部署方可以在 `conversation.execution.detail` 注册自己的组件来替换该主体。

步骤类别映射由本包自己拥有，而不是从 Chat 导入，因此两个界面对已记录工具名的分类互相独立。工具名是开放的：无法识别的名字是一个合法的 `tool` 步骤，并保留其记录下来的名字。

### 阅读一步的两半

一次工具调用会分两次到达。模型流式输出期间，`assistant/live-chunk` 分片携带调用的名字与参数片段，产生一行 `preparing`；这次尝试结算时，持久的 `tool/call` 与 `tool/result` 事件携带权威的名字、参数与结果，该行进入终态。丢掉全部实时分片后剩下的行完全相同，因为折叠把持久的一半当作结论。

推理同理。持久结算里的 `reasoning-chunks` 记录对文本与时间跨度都是权威的，并会覆盖实时增量累积的内容。该结算上的 `interrupted` 是轮次中途取消的已记录标记，因此被中断的推理会报告为 interrupted，而不是从轮次边界反推。

## 已知限制与延期工作

<a id="known-limitations-and-deferred-work"></a>

以下限制是当前包的约束，描述的是有意的范围而不是未完成的工作。

- **该视图是独立页签** —— 执行过程账本不与 Chat 共享行，因此读者需要切换视图而不是同时看到两者。这是让两套过程呈现互不重复的设计决定。
- **实时预览在结算时变短** —— 断线或重连会回落到持久结算，因此正在流式展示的推理可能在结算到达前显得更短。这是平台的瞬态/持久分工，不是已记录文本的丢失。
- **`unfinished` 是派生态而非记录态** —— 已关闭轮次中没有结果的调用会被报告为未完成。若将来出现把结果合法推迟到后续轮次的机制，该判断会出错。
- **账本只读** —— 它不提供输入框、审批或引导面；发送消息或回答问题仍在 Chat 中进行。
- **步骤类别按包各自分类** —— 本视图保留自己的工具名映射而不与 Chat 共享，因此新增一种工具类别需要在两处同时添加。
